# دليل نشر عقدة التبرع — librepay.tech/support

> الهدف: صفحة التبرع تستقبل on-chain **بنفس تقنية المنتج**: LibrePay Node يعمل
> بوضع cold BIP47 (كود دفع `6bv5…`)، وكل تبرع يولّد فاتورة بعنوان صامت جديد،
> والمانح يدفع على شاشة الدفع الحقيقية للعقدة. **لا عنوان ثابت منشور إطلاقاً.**
>
> التوافق مع الاستراتيجية التونسية («publish, don't operate»): هذه عقدتك
> الخاصة تستقبل تبرعاتك أنت فقط — مثل حسابك البنكي — وليست خدمة دفع لغيرك.
> العقدة لا تحمل أي مفتاح صرف (الوضع cold): لا يمكنها تحريك أموالك حتى لو
> اخترقت بالكامل.

## خياران — اختر أولاً ما يناسبك

| | **الوضع المدمج (جديد)** | **عقدة مستضافة (هذا الدليل)** |
|---|---|---|
| سيرفرات إضافية | **صفر** — المحرك داخل librepay.tech على Vercel | VPS صغير (~4€/شهر) |
| التفعيل | قيمتا بيئة في Vercel فقط | VPS + DNS + install.sh + معالج |
| سجل الفواتير | لا قاعدة بيانات — توكنات موقّعة ذاتية الاكتفاء | قاعدة بيانات العقدة + كشف دفع تلقائي |
| السحب | `scripts/recover-embedded-donations.ts` — انظر `docs/RECOVER_EMBEDDED_DONATIONS_AR.md` | `/cold` لكل فاتورة |
| يناسب | البدء الفوري بلا تكلفة ولا صيانة | من يريد كشف دفع آلي وسجلات كاملة |

الوضعان يستخدمان **نفس كود الدفع ونفس الرياضيات** — يمكنك البدء مدمجاً اليوم
وترقية نفس كود الدفع إلى عقدة كاملة لاحقاً دون أي تغيير عند المانحين. عند ضبط
`DONATION_NODE_URL` + `DONATION_API_KEY` في Vercel يتحول `/api/donate` تلقائياً
للعقدة (أولوية العقدة).

### تفعيل الوضع المدمج (≈ دقيقتان)

1. لوحة Vercel → المشروع → Settings → Environment Variables:
   - `LP_PAYMENT_CODE` = كود الدفع الخاص بك (يظهر في معالج العقدة أو صفحة cold)
   - `LP_DONATION_SECRET` = سلسلة عشوائية طويلة (مثلاً `openssl rand -hex 32`)
2. Redeploy.
3. زر التبرع الصامت على `/support` يعمل فوراً: فاتورة → `/pay/{token}` — شاشة
   دفع على موقعك نفسه بعنوان صامت جديد لكل تبرع وكشف وصول حي عبر مستكشف السلسلة.

## المعمارية

```
المانح على librepay.tech/support
  ├─ يختار مبلغاً (2,100 / 21,000 / 210,000 sats أو مخصص)
  ├─ POST /api/donate  (دالة على Vercel — تحمل مفتاح API server-side)
  │    └─ POST {DONATION_NODE_URL}/api/v1/invoices  (Bearer lp_live_…)
  │         └─ 201 { checkoutUrl }
  └─ تحويل تلقائي → https://node.librepay.tech/pay/{id}
       └─ شاشة الدفع الحقيقية للمنتج: عنوان صامت + QR + حالة الدفع
```

صفر تعديلات على كود العقدة — كل شيء يستخدم API العام الموثق في `docs/API.md`.

## الخطوات (≈ 30 دقيقة)

### 1) استأجر VPS صغير
- Hetzner CX22 (~4€/شهر) أو Netcup أو أي VPS أوروبي، Ubuntu 24.04، 2GB RAM.
- لا تضع أي بيانات شخصية في حساب الاستضافة أكثر من اللازم.

### 2) وجّه النطاق
- أضف سجل A في لوحة DNS لنطاق librepay.tech:
  `node.librepay.tech → IP الـVPS`
- انتظر انتشار DNS (`dig +short node.librepay.tech` يعيد الـIP).

### 3) ثبّت العقدة بأمر واحد
على الـVPS (كمستخدم عادي له sudo):

```bash
curl -fsSL https://raw.githubusercontent.com/radhwendalyhamdouni/librepay-node/main/install.sh | bash -s -- --domain node.librepay.tech
```

المثبّت يركّب Caddy بشهادة Let's Encrypt تلقائياً ويشغّل الخدمة، ثم يعطيك
**رمز إعداد لمرة واحدة**. افتح `https://node.librepay.tech/setup` وأكمل
المعالج داخل المتصفح.

### 4) أكمل معالج الإعداد (أهم خطوة)
- **الشبكة:** mainnet (الافتراضي).
- **المحفظة — اختر وضع cold BIP47:** أدخل **كود الدفع** (يبدأ بـ `6bv5…`)
  من محفظتك (Sparrow: علامة تبويب PayNym / غيرها عبر توليد كود دفع من
  مفاتيحك). العقدة تأخذ الكود العام فقط — **لا تلصق عبارة استرداد ولا xprv
  في أي حقل**.
- **اسم المتجر:** `LibrePay Node — donations` (يظهر على شاشة الدفع).
- **LP_BASE_URL:** `https://node.librepay.tech` (إن سأل المعالج).
- أنشئ **مفتاح API** في نهاية المعالج/لوحة التحكم — يظهر **مرة واحدة**
  (`lp_live_…`). انسخه الآن.

### 5) اربط المنصة بالعقدة (اختر إحدى طريقتين)
- **أرسل لي** الرابط والمفتاح في المحادثة وسأضبط متغيرات Vercel عبر الـAPI:
  `DONATION_NODE_URL=https://node.librepay.tech` و`DONATION_API_KEY=lp_live_…`
- أو بنفسك: Vercel → مشروع **librepay** → Settings → Environment Variables
  → أضف المتغيرين (Production) → Deployments → Redeploy.

بعد ذلك ينشط زر التبرع تلقائياً (الصفحة قبلها تعرض حالة «قريباً» رشيقة
وعلى Lightning يعمل دائماً).

### 6) أفرغ العنوان القديم
العنوان الثابت `bc1qctga…` أُزيل من الموقع نهائياً (commit b97fa12).
أرسل رصيده من محفظتك إلى حساب التبرعات الجديد (أو أي عنوان من كود الدفع)
بمبلغ يغطي الرسوم — ثم لا تستخدمه مرة أخرى.

## تشغيل الاستلام (كل فترة)

- العقدة تراقب وتعلن `settled` لكل فاتورة صامتة.
- لسحب تبرعات فاتورة معينة: صفحة `/cold` في العقدة تصدّر **WIF لكل فاتورة**
  — استورده في Sparrow وأنقل الأموال إلى محفظتك الباردة. العقدة نفسها لا
  تستطيع الصرف أبداً.
- راقب الحالة عبر `/api/system/status` أو إشعارات Prometheus المدمجة.

## الأمان — لماذا هذا آمن

- **العقدة أبداً لا تحمل مفتاح صرف**: كود الدفع بيانات عامة، الفواتير مشتقة
  منه، والصرف يتطلب مفاتيحك خارج العقدة (WIF لكل فاتورة).
- **مفتاح API يبقى server-side** في متغيرات Vercel — لا يصل للمتصفح أبداً.
- **حدود معدّل** مزدوجة: على المنصة (10 طلبات/دقيقة/IP) وفي العقدة (120/دقيقة).
- **المبالغ محدودة**: من 1,000 إلى 10,000,000 sats لكل تبرع.
- الشحنات كلها HTTPS عبر Caddy + Let's Encrypt.

## فحص ما بعد التشغيل (قائمة تحقق)

1. `curl -s https://node.librepay.tech/api/system/status | head` → يستجيب.
2. من صفحة /support: اختر 21,000 sats → زر التبرع → يجب أن يحوّلك إلى
   `/pay/…` على العقدة وتظهر شاشة الدفع بعنوان صامت `bc1…` مختلف عن أي
   عنوان سابق.
3. ادفع للمزامنة testnet-ذكاء: لا تدفع مبالغ حقيقية قبل فحص واحد — إن
   أردت اختباراً كاملاً بدون مخاطرة كرّر نفس الإعداد على VPS مؤقت بـ
   `LP_NETWORK=testnet` وvpub ثم احذفه.
4. تحقق أن العنوان القديم لم يعد يظهر في أي مكان على الموقع.
