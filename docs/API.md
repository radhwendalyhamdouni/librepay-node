# LibrePay Node — API v1

Fully self-hosted: the node depends on no external platform — only the Bitcoin
chain (Esplora API you configure) and your own webhook endpoints. The contract
is wire-compatible with the LibrePay platform, so a client written for
librepay.tech works against this node by changing the base URL and API key
only.

## Authentication

```
Authorization: Bearer lp_live_<48 hex>
```

The key is generated by `bun run setup` and lives in `LP_API_KEY`. Invalid or
missing keys get `401 {"error":"unauthorized"}`.

## Create invoice

```http
POST /api/v1/invoices
```

Request (Zod-validated):

| field | type | rules |
|---|---|---|
| `amountSats` | int | 1 … 2_100_000_000_000 — OR use `amountFiat`+`currency` |
| `amountFiat` | number | ≥ 0.01, with `currency` (`USD`, `EUR`…) |
| `orderId` | string? | ≤ 64 — your reference, echoed everywhere |
| `description` | string? | ≤ 140 — shown on checkout |
| `expiresInMinutes` | int? | 5 … 120 (default from `LP_INVOICE_EXPIRY_MINUTES`) |
| `metadata` | object? | keys ≤32 chars, values string/number/bool/null (≤256 chars) |

Response `201`:

```json
{
  "invoice": {
    "id": "m01abc…",
    "status": "waiting",
    "amountSats": "15230",
    "stealthAddress": "bc1q…",
    "derivationMode": "stealth",
    "expiresAt": "2026-09-28T12:00:00.000Z",
    "confirmationsRequired": 2
  },
  "checkoutUrl": "https://pay.example.com/pay/m01abc…"
}
```

Send the buyer to `checkoutUrl`, or render your own UI from `invoice`
(the stealth address + amount are enough for any QR).

Errors: `400 INVALID_INPUT`, `409 WALLET_NOT_CONFIGURED`, `503 RATE_UNAVAILABLE`.

## Invoice status

```http
GET /api/v1/invoices/:id
```

Response `200`: `{ "invoice": { … } }` — full row, sats as strings.

`status` lifecycle:

```
waiting → detected → confirmed → settled
waiting|detected → expired
underpaid (received < 99% of amountSats after confirmations)
```

**Release goods on `confirmed`** (default 2 confs, instant for Lightning).
`settled` (6+ confs) is the deep-finality signal.

## Webhooks

Configured via `LP_WEBHOOK_URLS` + `LP_WEBHOOK_SECRETS`. Every transition is
POSTed as JSON:

```json
{ "event": "invoice.confirmed", "invoiceId": "m01abc…", "data": { "invoice": { "status": "confirmed", "txid": "…", "…": "…" } }, "timestamp": 1790000000000 }
```

Headers:

- `X-LibrePay-Signature: sha256=<hex hmac-sha256(secret, RAW body)>` — verify
  timing-safe against the raw body before parsing.
- `X-LibrePay-Event`, `X-LibrePay-Delivery-Id`, `X-LibrePay-Timestamp`.

Respond `2xx` to acknowledge. Retries: 1m, 5m, 15m, 1h, 6h, 24h (~8 attempts),
then the delivery is marked `dead`. Deliveries are idempotent on your side —
the same event may arrive more than once.

Events: `invoice.detected`, `invoice.confirmed`, `invoice.settled`,
`invoice.expired`, `invoice.underpaid`.

## Public checkout payload

```http
GET /api/public/invoice/:id        # no auth — powers the hosted checkout
```

## Health & cron

```http
GET  /api/health                   # 200 {ok:true, db:true}
POST /api/cron/tick                # Bearer LP_CRON_SECRET — manual watch pass
```

## Simulation (testing only)

```http
POST /api/dev/simulate-payment     # { "invoiceId": "…" }
```

Settles an invoice without on-chain payment. Only exists when `LP_SIMULATE=true`.
**Never enable on a node expected to hold real money.**
